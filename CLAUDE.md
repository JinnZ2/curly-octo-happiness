# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A toolkit for cross-domain analysis: experimental Python "playgrounds" exploring AI grounding, claim falsification, dependency mapping, and geometric system diagnostics. Shared infrastructure lives in the `grounding` package; everything else is a runnable script or a design sketch.

## Running things

```bash
python garden.py                              # batch simulation, prints 100 steps
python unified_playground.py                  # interactive REPL (type 'exit' to quit)
python meta_playground.py                     # one "day" across all playgrounds
python diagnostic/systems_diagnostic_suite.py # SDS demo (needs networkx)
cd modules && python main.py                  # SDS pipeline (imports are CWD-relative)

python -m pytest tests/                       # test suite (needs pytest; networkx/numpy
                                              # for the SDS/plugin tests, else skipped)
```

Run root scripts **from the repository root** — they import the `grounding` package by relative path (or `pip install -e .` to make it importable anywhere). Interactive playgrounds (`unified_playground.py`, `weave*.py`, `relational_weave.py`) read from stdin in a loop; a single test is `python -m pytest tests/test_sds.py::test_fdm_max_depth_not_zero`.

Dependencies: the `grounding` package and root playgrounds are stdlib-only. Extras (see `pyproject.toml` optional-dependencies / `requirements.txt`): `modules/` and `diagnostic/` need `networkx`; most of `plugins/` needs `numpy`; `project/shape_board.py` needs `plotly` + `networkx`; `project/cognitive_playground.py` needs `torch`, `transformers`, `scikit-learn`, `numpy`.

## Architecture

- **`grounding/`** — the one canonical home of the previously copy-pasted core classes: `core/epsilon_machine.py`, `core/variety.py` (see the complexity/cybernetics layer below), `core/claims.py` (`Claim`, `DependencyTree` — with historical aliases `get_or_create`/`add_node`, `recalibrate`, `summary`), `core/graycode.py` (`gray_bits`/`gray_to_index`, the band-encoding convention every plugin uses), `core/memory.py` (`EpisodicMemory`, `MemoryStream`, `SharedMemory`), `core/mentor.py`, `worlds/bumpy.py` (`BumpyWorld`, `WorldModel`). `shared.py` is a re-export shim kept for `playground4-8_*.py`/`meta_playground.py`. Note: `Claim.status` is a **property** (string), not a method.

- **Epistemics layer** (`grounding/core/epistemics.py` + optional `Claim` fields). Claims can carry a machine-checkable `logical_form` ({"op": "abs_diff_lt", "args": [...]}) evaluated via `claim.evaluate(bindings)` — the single source of truth for the falsification condition — plus `scope`, `reference_class`, an executable `refutation_test`, and an escape-hatch counter (`reformulate()`); `beta_confidence` is the calibrated Beta-posterior alternative to the step-heuristic `confidence`. `classify_falsifiability` routes unfalsifiable claims to the `UnknownJournal` (see the agent's `claim <text> :: <falsification>` command). `check_geometry_units` validates the `_v`/`_K`/`_pa`-style key-suffix unit convention (opt-in via `PluginManager(unit_checks=True)`); `check_with_z3` cross-checks logical forms when `z3-solver` is installed. FDM knowledge bases live in `data/*.json` (`FractalDependencyMapper.from_json`).

- **Playground line** (repo root). `claim_falsification_garden.py` → `garden.py` → `garden_with_tree.py` (physics/claims) and `relational_weave.py` → `weave.py` → `weave_with_memory.py` (conversation) merge into `unified_playground.py` — the current agent (Ari: experiments, chat, dreams, skill lab, hardware encoder). `playground4-8_*.py` are standalone sketches of individual subsystems; `meta_playground.py` runs one cycle of everything. Historical versions live in `design/archive/` (v1–v6; there was never a v4) — read-only, do not extend them.

- **Plugin/encoder system**. `plugin_manager.py` (single, consolidated) scans `plugins/` for modules exposing `PLUGIN_META` (`name`, `description`, `class_name`; legacy `encoder_class` accepted). Read paths, in priority order: extended `to_binary(state, prev_state, cross_signals)`, `process(geometry)`, then `from_geometry()/to_binary()`. Classes needing constructor args (`harmony_field_engine`, `vector_pole_extension`, …) register as **services**; get them via `pm.get_service(name, *args)`. Plugins encode sensor data into Gray-coded bitstrings using band thresholds (`grounding.core.graycode` convention: highest band whose threshold ≤ value).

- **Coupling / synchronizability** (`grounding/core/coupling.py`). Master Stability Function machinery for multi-unit networks, motivated by fragmentation and disconnects. Two independent halves: topology (`spectrum` → Laplacian eigenratio λ_N/λ_2, `components` → who is on which side of a partition) and dynamics (`estimate_msf_window` → the MSF's negative region, **computed** from the node dynamics by transverse Lyapunov exponent, never supplied). `synchronizable` is the Barahona–Pecora eigenratio criterion: topology on the left, dynamics on the right. Key discipline — the interior coupling optimum is a **Class III** property, not a law: `ThermalWorld` units are Class II (a threshold, no optimum), so `coupling_coherence` reports f(C) as binary for them rather than inventing a gradient. Scalar real dynamics can *never* be Class III; a bounded window needs a vector variational equation (Rössler is the test case). A disconnected network reports `FRAGMENTED_STRUCTURALLY` — λ_2 = 0 means no coupling strength works, which is a fact about the graph, not a mistuning. `grounding/core/linalg.py` holds the one canonical symmetric eigensolver (stdlib Jacobi, numpy as accelerator); `modules/gae.py::graph_energy` uses the same one.

- **Dormancy / reverse bloom** (`grounding/core/dormancy.py`). `bet_monolayer()` derives the residual floor from a measured sorption isotherm (Brunauer–Emmett–Teller): below the monolayer the remaining water is structurally bound, so drying exposes the macromolecular surface rather than protecting it. Measured optima are species-specific (~0.057 maize, ~0.02 safflower), so `MIN_VIABLE_RESIDUAL` is a default to replace with a measurement. The fold cost is *derived*: `erasure_cost` counts the bits folding destroys (magnitude, phase, history) after Landauer, so the window closing before death is a consequence of erasure having a positive floor rather than a chosen constant — and a bigger or older structure genuinely costs more to fold. `fold()` refuses to guess the energy budget: name it with `energy=` or `energy_term=`. The other half of the partition story: `coupling.py` says a network split and who is on each side; this says what the cut-off side does. `fold()` collapses a structure to proportions summing to 1 (`SeedState`) — every ratio kept exactly, magnitude discarded to `conserved_total`, and `lost` states plainly what folding destroys (magnitude, history, phase). `unfold()` re-blooms at whatever scale the ground now supports; a degraded seed re-expands **smaller, never distorted**. `viability()` is Ellis & Roberts' 1980 seed equation with residual activity as moisture and stress as temperature — disclosed as an analogy on every reading. Three refusals are the point: an empty structure cannot be folded, over-compression below `MIN_VIABLE_RESIDUAL` is *charged* rather than rewarded (same sigma, worse outcome), and `assess_dormancy(None)` returns `NEVER_FOLDED` — absent evidence, not proof of death, which is the untested-is-not-refuted rule reached from the other direction.

- **Worlds**. `grounding/worlds/bumpy.py` (`BumpyWorld`, `WorldModel`) is the original 1-D toy — fine for staking claims, poor for *measuring* a regulator: unbounded state, a non-stationary residual even when healthy, and no body in the loop. `grounding/worlds/thermal.py` (`ThermalWorld`, `ThermalModel`) is the substrate built to fix all three — hold a part in a temperature band against mean-reverting cold. Bounded (temperature relaxes toward ambient), stationary under a fixed policy, and **embodied**: heater `efficiency` is a plant parameter, so `ThermalModel.learned_gain()` tracks it exactly and damage is identifiable. Its dynamics are control-affine, so `core/safety.py`'s barriers are exactly right for it rather than approximately. `causal_dag()` is checked against `step()` by finite-difference sensitivity in `tests/test_thermal.py` — both that declared edges are real and that undeclared dependences do not exist. **Persistent excitation is required**: a controller that is a deterministic function of ambient makes the plant unidentifiable (learned gain ~0.25 vs true 6.0); dither 0.4 recovers it. That is why anything measuring residuals here needs the agent to keep exploring.

- **Sensor bus / event encoding** (Phase 3.6). `grounding/core/events.py::EventEncoder` — DVS-style encoding over the repo's bands: an event fires on a **band change** plus a value hysteresis, not on a raw value distance (equal-occupancy bands are unevenly spaced, so a uniform threshold misses crossings exactly where the signal lives). Reporting every band change is lossless and still saves ~82% of traffic on a slow signal; `fidelity_claim` stakes the compression so any further saving has its band error measured rather than assumed, and `retune()` drives the event rate to a target as a control loop. Behind the agent's `events [hysteresis]` command.

- **Sequential monitoring** (`grounding/core/damage.py`). `DamageDetector.scan()` is a fixed-sample test — sound once on a settled model, unsound run every step. `SequentialDamageDetector` is CUSUM, parameterised by **ARL0** (observations per false alarm) rather than a sigma level, with `arl0_for`/`decision_interval_for` implementing Siegmund's approximation. **Do not trust the theoretical threshold on this repo's streams**: ThermalWorld's residual has lag-1 autocorrelation 0.74, and a designed ARL0 of 1000 delivers an empirical 7.8. Use `calibrate_from(in_control_stream)`, which measures the threshold on real data (50× inflation over theory), reports the gap, and refuses samples shorter than ~10×ARL0.

- **Embodiment / safety layer** (Phase 3.1–3.2 of `PLAN_FORWARD.md`). `grounding/core/safety.py` — `Barrier` + `SafetyFilter` implement CBF runtime assurance with **no QP dependency**: the constraint `L_f h + L_g h·u >= -α(h)` is linear in `u`, so one constraint is a closed-form half-space projection and several are Dykstra alternating projections; `SafetyDecision` reports `converged` and `feasible` separately, and infeasible means *no safe control exists here*, not a solver bug. `safety_claim` stakes a safe set as machine-checkable (`h >= 0`), and a falsified safety claim raises an algedonic signal. `thermal_barriers`/`battery_barrier` are the plan's coupled cold-environment set. `FallbackCatalog` pairs each failure mode with its repurposed capability **and** the envelope recomputed on degraded dynamics — the same shorted diode is a conductor at 20 °C and refused at 60 °C. Wired via `UnifiedAgent.degraded_plant/safety_check/fallback_for` behind the commands `safety`, `fallback`, `catalog`, `ambient`. Note `VirtualComponent.apply_stress` now takes `ambient_c`; without it the component's temperature ignored the environment and the thermal floor could never bind.

- **Good-regulator / allostasis layer** (Phase 2.1–2.3 of `PLAN_FORWARD.md`). `grounding/core/regulator.py` — `CausalDAG` (worlds state their causal structure; `BumpyWorld.causal_dag()`), `check_homomorphism` (does the claims tree preserve the world's causal edges? collapsing variables is legitimate abstraction, losing a primitive root is not; unmapped variables are handed to HND), `regulator_score` = 1 − H(outcomes)/H_max over **tested** claims. `grounding/core/allostasis.py::AllostaticBands` — reactive vs anticipatory band shifts, each charged to a cumulative `load`, with `chronic()` for pay-forever-fit-never and `miscoverage` measured as band utilisation. Both behind the agent's `regulator` and `bands` commands. `modules/transition.py` measures antifragility properly: mean-preserving spread with common random numbers, viability test (convexity while ruined is the floor at zero, not resilience), and Taleb's fragile/robust/antifragile triad. Note the measured result contradicts the plan's prediction — TORUS is robust, not antifragile — and `tests/test_sds.py` pins that.

- **Cybernetic architecture** (Phase 1 of `PLAN_FORWARD.md`). `grounding/core/vsm.py` — Beer's five systems as real routing: `ViableSystem.route()` walks S1→S2→S3→S5 and can be attenuated at any hop, `raise_algedonic()` goes S1→S5 consulting no mediator, and every `Signal` carries the `path` it travelled so `bypassed_mediation` is checkable per message. Also `saturated()` (an alarm channel that always fires is not an alarm) and `SecondOrderGuard` (von Foerster eigenvalue drift: self-confidence rising while independent error does not fall). `grounding/core/mentor.py::TeachbackMentor` — Pask teachback as staked claims; the automatic overlap check abstains at low overlap, rewordings go through `claim.reformulate()`, and an escape-hatched concept is never `learned()`. Wired into `unified_playground.py` (`UnifiedAgent._build_vsm`, `hardware_scan`, `self_model_check`) behind the commands `vsm`, `pain`, `self-check`, `explain … :: …`, `teachback … :: …`, `confirm`, `correct … :: …`, `learned`. Note `explain <concept>` (asks the tree) and `explain <concept> :: <text>` (mentor teaching) are different commands, disambiguated by the `::`.

- **Complexity/cybernetics layer** (Phase 0 of `PLAN_FORWARD.md`). `grounding/core/epsilon_machine.py` — CSSR-style causal-state reconstruction (`reconstruct`, `symbolize`, `equalized_history_length`) yielding statistical complexity `C_mu` and entropy rate `h_mu`; phases I–II only, so read it comparatively, not as an absolute. It backs `HiddenNodeDetector.scan(..., acceptance="epsilon_machine")`, which keeps a correlated candidate only if conditioning on it drops **both** `C_mu` and `h_mu`. `grounding/core/variety.py` — `VarietyMeter`, Ashby's `V(Z) >= V(D) - V(R)` as an alarm; wired into `plugins/physics_discovery.py` (`variety_status()`, `run_full_discovery(trigger="novelty"|"variety"|"either")`) so band expansion fires when the encoders run out of distinctions, not only on out-of-range data.

- **Systems Diagnostic Suite (SDS)**. Canonical implementation in `modules/`: `gae.py` (`GeometricApplicabilityEngine.analyze(nodes, edges)`, plus constructor-style `GAE(nodes, edges).analyze()` wrapper; always reports Sinha–de Weck structural complexity, graph energy, hub concentration and attack tolerance, and with `complexity_scoring=True` lets hub fragility boost TORUS/ICOSAHEDRON), `hnd.py`, `fdm.py`, `transition.py`, `main.py::diagnose_system()`. `diagnostic/systems_diagnostic_suite.py` is a compatibility shim (short names `GAE`/`HND`/`FDM`) + runnable demo. `project/` connects GAE to a plotly "Shape Board" (`shape_board.py` has all five shape generators; `gae_shape_connector.py` reaches `diagnostic/` via `sys.path`).

## Repository conventions and gotchas

- **Hypothesis engine**: `scripts/hypothesis_engine.py` — a stdlib-only, deterministic weekly research pipeline (explore free scholarly APIs → log → stake `Claim`s → cross-source test → reformulate/escape-hatch → hidden-variable scan → hypothesis drafts). It stakes into the repo's own `grounding.core.claims` machinery rather than reimplementing it; `he.DependencyTree` is an id-keyed claim registry wrapping the repo tree. Config in `config/topics.json`, design doc at `design/hypothesis_engine.md`, offline tests in `tests/test_hypothesis_engine.py` (`--dry-run` uses `scripts/sample_findings.json`, no network). Outputs (`data/*.jsonl`, `data/claim_tree.json`, `hypotheses/*.md`) are generated and committed by `.github/workflows/hypothesis-engine.yml`. The first live run (2026-08-17, both jobs green, arXiv + Crossref both answering) exposed two things the offline tests could not: the stage-6 hidden-variable scan zipped residuals to candidate series **by list position** — claim-stake order against chronological order — so it reported a spurious driver that moved when the same data was reordered; it now shares one `TimeGrid` between both sides, placing each claim by its finding's date. The gates that replaced it are quantities rather than conventions: `beta_precision` weights each claim by the Fisher information of its own Beta posterior (an untested claim and one tested 20 times to a dead heat both read 0.5, and only the variance separates them — 12 against 172), `weighted_partial` controls for the clock because `findings_volume` correlates with elapsed time at 0.876 all by itself (Reichenbach), and `description_length_gain` (Rissanen MDL in Schwarz form, charged against Kish's effective sample size) replaces α=0.05. Two traps worth remembering: MDL alone would *not* have caught the false positive (+2.3 bits — its job is removing the arbitrary threshold, not rejecting), and precision weighting alone cannot either, since equally-uninformative claims get equal weights — hence the absolute `MIN_STANDING_TESTS` floor. **And all of that principled machinery still left the scan firing on 36% of corpora with no driver in them** — two MDL accounting bugs (`k=1` where the clock is a second fitted term; no `log2(m)` charge for picking the best of *m* candidates, dropped along with Bonferroni) plus no floor on effective sample size. `calibrate_scan` measures false-positive rate *and* power on synthetic corpora and returns the loosest `MIN_EFFECTIVE_SAMPLE` holding a 5% rate on the Wilson upper bound, refusing targets it cannot resolve — same contract as `damage.py::calibrate_from`, and it overrode my eyeballed 6.0 (0.4% FPR, 38.6% power) in favour of a measured 5.0 (3.7%, 58.1%), because a gate tightened past its target is not safer, only deafer. `python scripts/hypothesis_engine.py --calibrate` prints the curve; the scan still misses ~2 real drivers in 5, which is an argument for the ε-machine criterion rather than for loosening this. `accept_by_epsilon_machine` in `modules/hnd.py` is the criterion this should become, but it needs 30–240 observations per topic (~4 to ~27 weekly runs of accumulation), so the correlational test is an explicit stopgap. Retractions are appended, never deleted (`retract`/`standing_suggestions`) — Landauer, as `dormancy.py` already argues it: erasure is the irreversible operation, and a log that silently loses its mistakes cannot be told from one that never made any. And `stage_modify` runs before `stage_hidden`, so `Claim.reformulate()`'s (correct) reset of `passed`/`failed` leaves reformulated claims at `beta_confidence` 0.5 — the report now states standing evidence alongside the run's test counts, because the two differ a lot.

- **Sketches vs. code**: `design/archive/`, `design/notes/` (research notes, index at `00_INDEX.md`), root `PLAN_FORWARD.md` (phased roadmap those notes feed), `design/hypothesis_engine.md`, and `project/Organize.md` are non-runnable history/notes/plans. The `.md` files in `plugins/` are wiring snippets for `UnifiedAgent.handle_mentor` (each states its target at the top); `plugins/Light_bridge.md` documents `plugins/light_bridge.py`.
- **Dependency tiers** (stated in `pyproject.toml`): `grounding/` and the root playgrounds are **stdlib-only, deliberately** — the stewardship line is about running where parts and bandwidth are scarce, so the core must work on a bare Python install. Nothing in the core may import an optional dependency *even guarded*, since `try: import numpy` makes core behaviour depend on what happens to be installed. Everything heavier goes behind an extra and must **add** capability rather than replace it: `modules/gae.py::graph_energy` is the pattern — numpy when present, a stdlib Jacobi solver when not, with a test asserting the two agree to 1e-8. Phase 3.3/3.4 (flow-matching policy, learned latent planner) are the first items that genuinely need the `ml` extra; everything through Phase 3.2 and 3.5 fits in tier 0.
- No packages outside `grounding/`: `modules/`, `plugins/`, `diagnostic/`, `project/` rely on their own directory being on `sys.path` (scripts there assume CWD or add paths themselves; `tests/conftest.py` handles it for tests).
- When adding an encoder plugin, use `grounding.core.graycode.gray_bits` semantics for banding and declare `class_name` in `PLUGIN_META`; adaptive banding goes in an `init_bands(samples)` method.
